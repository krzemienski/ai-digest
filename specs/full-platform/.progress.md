# Progress: full-platform

## Original Goal

AI Digest — Full-Stack AI News Aggregation Platform with Podcast Generation, Newsletter Delivery, Research Agents & Cyberpunk UI

Build a complete AI news aggregation platform that:
1. **Ingests** content from multiple sources (RSS, GitHub, HuggingFace, ArXiv, Reddit, HackerNews)
2. **Analyzes** via Claude Agent SDK research agents (categorization, relevance scoring, synthesis)
3. **Generates** a daily digest with editorial synthesis
4. **Produces** a multi-speaker podcast via 11 Labs audio generation
5. **Delivers** a cyberpunk-themed newsletter to subscribers
6. **Presents** everything through a cyberpunk dark-themed web app (Next.js + Tailwind) with mobile-ready Nativewind components
7. **Configures** all parameters (models, voices, sources, schedule) through an admin dashboard

The UI/UX layer uses Stitch MCP for design reference generation (see companion spec `poc`), with implementation in NativeWind/React Native-compatible components.

Two personas: Consumer (reads digests, listens to podcasts, subscribes to newsletters) and Developer (configures pipeline, monitors research logs, manages sources).

_New from full-platform research:_
- Claude Agent SDK (`@anthropic-ai/claude-agent-sdk`) supports subagents with per-agent model selection (haiku/sonnet/opus)
- SDK provides `maxBudgetUsd` for cost capping and `maxTurns` for runaway prevention
- Daily agent pipeline estimated at ~$0.90-2.00/day in Claude API costs
- ElevenLabs JS SDK (`@elevenlabs/elevenlabs-js`) supports cross-segment continuity via `previous_request_ids` for natural podcast concatenation
- ElevenLabs Creator plan ($11/mo) covers ~100 min audio, sufficient for ~5-10 episodes/month
- No single "generate podcast" API exists -- must build: script -> split by speaker -> TTS per segment -> ffmpeg concat
- Resend is the recommended email provider: React Email integration, 3K free emails/mo, 1K free contacts
- ArXiv API requires no auth, max 2000 results per request, 3-second delay between requests
- Reddit API now requires pre-approval (2025 change) -- RSS fallback recommended for subreddits
- HN Algolia API is free, no auth, generous limits -- best low-friction source
- Turborepo recommended over Nx for small-team greenfield (10-min setup, 3x faster on small projects)
- Drizzle ORM recommended over Prisma: ~7kb bundle, zero cold start, no codegen, serverless-friendly
- Cloudflare R2 has zero egress fees (critical for audio streaming) vs S3's $0.09/GB
- BullMQ + Redis provides job persistence, resumable pipelines, cron scheduling, and flow dependencies
- Railway recommended for deployment: persistent containers, built-in Postgres/Redis, cron support, $5-20/mo
- Vercel unsuitable for long-running agent pipelines (serverless timeout limits)
- Zustand preferred over React Context for audio player state (selector-based, avoids re-render cascade)
- No existing project combines TS/Next.js + Claude agents + multi-source + podcast + newsletter -- genuine gap
- Estimated monthly cost: ~$62-92/mo (Railway + Claude API + ElevenLabs + R2)

_New from design phase:_
- Architecture is monorepo monolith: single Next.js app (apps/web) + BullMQ worker (apps/worker) + 5 packages (agents, db, email, podcast, shared)
- Ingestion and normalization stages are pure TypeScript (no Claude API calls) -- saves cost; only categorize/score/dedup/synthesize use LLM
- Claude Agent SDK structured output mode (JSON schema) minimizes token waste for categorization and scoring
- BullMQ FlowProducer models pipeline as parent-child job DAG -- ingestion sources run as parallel children, analysis stages are sequential
- PostgreSQL full-text search (GIN-indexed tsvector) sufficient for <100K items -- avoids Elasticsearch/Meilisearch infrastructure
- Separate worker process (apps/worker) required -- BullMQ consumers must run independently of Next.js to avoid blocking web requests
- Railway needs 3 services minimum: web (Next.js), worker (BullMQ), cron (trigger) plus Postgres + Redis add-ons
- Admin auth uses httpOnly + secure + sameSite=strict cookie set after API key validation -- simplest secure approach for v1
- Upstash Redis recommended for rate limiting (separate from Railway Redis) -- serverless-friendly sliding window
- Unsubscribe requires signed token in URL to prevent unauthorized unsubscribes -- security consideration
- R2 multipart upload needed for audio files approaching 50MB threshold
- Design yields ~120+ files total across all packages -- 17 implementation steps identified
- Cyberpunk design tokens defined: 11 colors, 3 glow shadows, font stack (JetBrains Mono + Inter via next/font/google)
- Server Components for all data-fetching pages (digest feed, episode library, archive) -- zero client JS for initial load
- "use client" only for interactive components: audio player, forms, admin dashboard controls
- 10 database tables with JSONB columns for flexible metadata (sources.config, normalized_items.metadata, episodes.voice_config)
- Deterministic item IDs via SHA-256 hash of source + sourceId -- enables idempotent ingestion without UUID collisions
