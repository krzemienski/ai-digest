## Original Goal

AI Digest — Full UI/UX Redesign via Stitch MCP with Cyberpunk Dark Theme (Mobile-First)

Complete UI/UX redesign of the AI Digest application using Stitch MCP for screen generation with a cyberpunk dark theme. Mobile-first approach covering 26 screens including: splash, onboarding flow, daily digest feed, podcast player (full + mini), newsletter archive/reader, configuration dashboard, research log pipeline monitor, search overlay, user profile, empty states, error screens, notification center, transcript view, share sheet, weekly summary, email newsletter template, and desktop variants (dashboard + admin panel). Design language: neon cyan/magenta/electric blue accents on deep black backgrounds, monospace headings, scanline overlays, glow effects. Implementation targets Nativewind/React Native with Tailwind design tokens.

## Learnings

- @expo-google-fonts packages export font constants that match useFonts key names exactly (e.g., JetBrainsMono_400Regular)
- expo-splash-screen preventAutoHideAsync must be called at module level (before component renders) to avoid flash
- react-native-track-player v4.1.2 installs cleanly in Expo managed workflow via `npx expo install`
- RNTP UpdateOptions uses `forwardJumpInterval`/`backwardJumpInterval` (not `jumpInterval`) and `progressUpdateEventInterval` for auto progress events
- RNTP PlayerOptions `maxCacheSize` is in kilobytes (not bytes), so 50MB = 1024*50
- For Expo Router apps, do NOT create index.ts entry point -- expo-router handles it; playback service setup goes in hooks/layout instead
- Episode.audioUrl is `string | null` and Episode.durationSeconds is `number | null` -- need null handling when building TrackPlayer AddTrack
- Expo Router (tabs) group: root index.tsx can use `<Redirect href="/(tabs)" />` to route into tab layout; (tabs)/index.tsx becomes the Home tab screen

- Our Stitch MCP has 6 tools: create_project, get_project, list_projects, list_screens, get_screen, generate_screen_from_text. Notably MISSING: extract_design_context and fetch_screen_code (available in Kargatharaakash variant). Design consistency must be managed via prompt templates.
- Stitch device types include MOBILE, DESKTOP, TABLET, and AGNOSTIC (not just MOBILE/DESKTOP as initially assumed)
- Stitch free tier: 350 Flash + 50 Pro generations/month. 26 screens + revisions (~52 total) uses only ~13% of budget.
- Electric Blue #0066FF FAILS WCAG AA for normal text (4.09:1 ratio vs 4.5:1 required). Must lighten to ~#3388FF or restrict to large text/decorative use only.
- All other proposed neon colors pass WCAG AA on #0A0A0F background. Cyan and Green pass AAA.
- NativeWind v4/v5 supports CSS variables via vars() function for runtime theming -- ideal for design token architecture.
- JetBrains Mono and Space Mono both available as Expo Google Fonts packages with useFonts hook.
- Android enforces max 5 tabs in bottom tab bar -- matches the 5-tab spec exactly.
- Mini player pattern: must use gorhom/bottom-sheet or react-native-reanimated for expand/collapse. PanResponder has known conflicts with scroll views.
- Email dark mode: avoid pure #000000 and #FFFFFF (auto-inverted by Gmail iOS). Use off-black #0D0D14 and off-white #F0F0F5.
- Email meta tags required: color-scheme and supported-color-schemes for Apple Mail dark mode support.
- Stitch generation takes several minutes per screen. Do not retry on timeout -- check with get_screen later.
- Project is greenfield: no existing code, no package.json, no tech stack decisions locked in.
- Requirements organized into 28 user stories across 11 feature areas with 22 functional requirements and 15 NFRs
- Two personas identified: Consumer (reads/listens) and Developer (configures pipeline) -- each has distinct screen sets
- P0 screens: daily digest feed, digest detail, full podcast player, mini player, tab navigation -- these form the MVP core
- 7 unresolved questions remain: transcript format, audio source, email service, desktop target, Stitch API status, content moderation workflow, state management library
- Scope creep is highest risk -- 26 screens is ambitious; strict P0/P1/P2 tiers enable deferral of P2 items (summary, email template, desktop) if needed
- Email template is isolated scope: different tech constraints (inline CSS, system fonts, no JS) -- can be built independently
- CRITICAL: Web app uses iron-session httpOnly cookies for auth -- React Native CANNOT use these. Must add JWT Bearer token support to login endpoint (~50 LOC server change). Mobile sends `X-Client-Type: mobile` header; server returns JWT in response; mobile stores in expo-secure-store.
- Web app already has a Zustand audio store at `apps/web/src/stores/audio-store.ts` -- mobile store should mirror this state shape (currentEpisode, isPlaying, currentTime, duration, playbackSpeed, transcript) but make actions async (delegate to TrackPlayer)
- All API routes follow `{ success: boolean, data?: T, error?: string, meta?: {...} }` envelope -- matches `ApiResponse<T>` from packages/shared
- packages/shared exports all types needed by mobile: Digest, Episode, Transcript, TranscriptSegment, PipelineRun, PipelineStage, Subscriber, SourceConfig, DigestConfig, ApiResponse
- TranscriptSegment has { speaker, text, startTime, endTime } -- answers the "transcript format" question from research: JSON with timestamps, not SRT/VTT
- Pipeline trigger POST body must be `{ triggerType: "manual" }` (not `triggeredBy: "admin"`) -- confirmed from existing codebase
- Admin auth uses `requireAdminFromRequest()` which checks iron-session -- needs Bearer token alternative path for mobile
- Server has rate limiting (60 req/min on search, episodes by ID) -- mobile must handle 429 Too Many Requests gracefully
- Newsletter appears to reuse digest model (no separate newsletter table) -- newsletter archive = digests that were emailed; need to confirm this assumption
- Monorepo uses pnpm 8.6.0 with pnpm-workspace.yaml -- apps/mobile fits naturally as `apps/*` glob matches
- metro.config.js needs special config for monorepo symlink resolution (packages/shared must be watchable)
- React Query (TanStack Query) chosen for server-state caching + Zustand for client-only state -- this separation avoids manual cache invalidation while keeping audio/auth state simple
- gorhom/bottom-sheet snap points [64, "95%"] for mini-player (64px collapsed) to full-player (95% expanded) -- single BottomSheet component in tab layout, content switches based on isExpanded

- Web app uses `jose` pattern is best (lightweight, ESM-native JWT library) rather than jsonwebtoken (CJS, heavier).
- Root turbo.json has `check-types` task -- mobile package just needs to add `"check-types": "tsc --noEmit"` to scripts.
